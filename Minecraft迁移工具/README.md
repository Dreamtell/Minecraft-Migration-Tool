# 🧳 Minecraft 存档迁移工具（迁移工坊）

一款用于在不同 Minecraft 整合包实例之间迁移 **模组、配置文件、存档和设置** 的图形化工具。

纯 Python + Tkinter 实现，**完全免费、开源、纯中文界面**，无需联网即可完成核心迁移（模组联网搜索为可选用途）。

---

## ✨ 功能特性

### 🚀 核心迁移
- **一键迁移**：从旧版（源）整合包复制到新版（目标）整合包，保留你的自定义配置与存档
- **四步迁移流程**：模组 → `options.txt` → 存档（`saves/存档名`）→ `config` 内容
- **模拟运行**：勾选后只预览将执行的操作，不实际改动任何文件，放心调整
- **迁移前磁盘空间检查**：自动校验目标磁盘能否容纳「迁移数据 + 目标备份」，不足时给出拦截
- **备份与回滚**：迁移前自动备份目标实例的 `mods / config / saves`，出问题可一键恢复
- **迁移历史记录**：记录每次迁移的时间、来源、目标、模组与 config 数量，支持回滚标记

### 🧩 模组差异识别
- **元数据级差异扫描**：读取 jar 内的 `fabric.mod.json` / `META-INF/mods.toml`，按 `Mod ID` 与版本号识别差异（支持 Fabric 与 Forge）
- **三类状态**：新增、更新、目标独有
- **按状态批量选择**：一键全选「新增」「更新」「目标独有」
- **智能排序**：按文件名、状态、类型、Mod ID、版本、大小排序
- **双击查看详情**：查看完整元数据（作者、描述、依赖等）

### 🔍 联网搜模组（可选）
- 基于 **Modrinth 公开 API**（免费、无需密钥）
- **最相似匹配**：本地模组自动匹配最相似的项目，自动置顶
- 展示最新版本、下载量、下载/项目链接，支持复制与跳转
- 只读搜索，不修改任何本地文件；无网络时核心迁移功能不受影响

### 📁 清单管理与放大查看
- **三个清单共用一个区**（标签页 `🧩 模组清单 / ⚙️ config 清单 / 📦 其它文件`）：
  模组清单和 config 清单原来各占一块 LabelFrame、都被 expand 拉到 ~240px，
  再加一个就没地方了；现在三页共用一块，**内容需求高从 679px 降到 557px**，
  标签上还带条数徽章（`📦 其它文件 12`），条数一变就刷新（防抖 300ms）
- **📦 其它文件清单**：带走 mods / config / saves 之外的东西 —— `shaderpacks/`、
  `resourcepacks/`、`options.txt`、`servers.dat`、`kubejs/`、`scripts/`……
  路径**相对整合包根目录**（不是相对 config），文件或文件夹都行、文件夹递归复制（含空目录）。
  页里可选**同名冲突策略**：`覆盖（先备份）`（默认，和别的清单一致）/ `跳过（目标保持不动）`，
  存配置键 `extra_conflict`；迁移日志里会写清"成功 N 个 / 跳过 N 个 / 失败 N 个"
- 模组清单 / config 清单可手动编辑、从源目录导入、拖拽添加
- **放大查看窗口**：可多选（勾选排序）、搜索、检测存在性、添加/删除、拖拽
- **两套实现可选**（设置 →「放大查看窗口」）：PySide6 试点窗口 / 经典 Tk 窗口
- **打开时用哪个视图也能选**（设置 →「放大查看窗口」→ 打开时用哪个视图）：
  `📋 表格视图`（默认）/ `🗂 卡片视图`，存在配置键 `big_view_view`，
  两次打开之间随时点窗口里的按钮切换，设置只管"刚打开时是哪个"
  - 试点窗口用**系统原生窗口框**：弹出/关闭/最小化走 Windows 自己的动画，圆角与深色标题栏
    交给 DWM（和 Tk 窗口同一套属性，`WS_EX_LAYERED=0` 才不会让 DWM 跳过动画）
  - 卡片视图：图标/中英名/版本/分类 chip/描述；选中蓝底 + 左侧高亮条逐帧动画
  - 按钮：悬停浮起并扫过一道光、按下沉下去再弹回（`QVariantAnimation`，单次重绘 0.3ms）
  - 单击=选中/取消、**双击=详情**（走 Qt 自己的 `doubleClicked`，间隔 0.175s，
    见下面的 🖱 一节；双击只"打开看看"，会把第一次单击造成的选中撤回来）
  - **🌐 联网搜索**（模组清单）：搜 Modrinth、最相似项置顶标 ★、双击打开项目主页，
    可打开下载页 / 复制下载链接；⬆ 标记比本地更新的版本
  - **平滑滚动**：滚轮逐帧缓动（泵每帧一步、按真实经过时间换算缓动，和 Tk 版同一套手感），
    表格一格 3 行 / 卡片一格 1 张；连续滚轮只累加目标，快速滚动不丢格
  - 详情窗/确认框/选文件框全是**非模态**的：它们开着的时候主界面照样能点能滚
  - 其余快捷键：右键=菜单、Esc=关闭、Del=移出清单、Ctrl+A 全选、Ctrl+F 搜索
  - 主窗口仍然是 Tk，Qt 窗口由 Tk 每 12ms 驱动一次事件循环，关掉它不影响主界面
  - **窗口图标**：Qt 不设图标时标题栏/任务栏是 Windows 那个通用占位图标（和主窗口的
    `1.ico` 完全不是一个东西），所以在 `ensure_app()` 里 `setWindowIcon(1.ico)` 设成
    应用级默认图标，放大查看/详情/联网搜索全都跟着用；闪屏子进程也单独设了一遍
  - 实测：第一次打开约 0.8～1.3s（Qt 首次建窗的一次性开销），之后每次约 0.1s
- **新添加高亮**：本次会话新加的模组用黄色高亮提示
- **实时刷新**：放大查看窗口会随主界面清单的外部变更自动更新
- **实时存档检测**：输入存档名即实时显示“存档是否存在”，无需手动点按钮

### 🖱 双击判定：**直接用框架自带的双击事件**（不再自己算间隔）

程序里没有"两次点击间隔 ≤ X 秒"这种判定代码了，全部交给框架：

| 位置 | 用的事件 | 多快算双击 |
| --- | --- | --- |
| 放大查看窗口（Qt 试点，默认后端） | `QAbstractItemView.doubleClicked` | **0.175s**（`qt_big_view.DOUBLE_CLICK_MS`，启动时 `setDoubleClickInterval`） |
| 卡片视图 / 模组差异列表 / 放大查看的 Tk 表格 | Tk `<Double-Button-1>` | **Windows 的"双击速度"**（默认 0.50s） |

- **单击 = 选中/取消，双击 = 打开详情**，两条互不干扰
- 双击**完全不改变高亮**：Tk 对第二次按下只发 `<Double-Button-1>`（它比 `<Button-1>` 更具体，
  实测确认），所以第一下单击造成的选中变化要在双击回调里撤回来；Qt 侧同理，双击回调里
  瞬间恢复原状态并吃掉紧随其后的那次 `clicked`
- **Qt 侧那个数是用户按手感试出来的**：从 1.50s 一路往下调（1.50s 时反馈"间隙大了"：点一下、
  隔一秒再点一下也被并成双击），最后定在 **0.175s** —— 两次单击绝不会被并成双击，只有很快
  的两下才算双击；更慢的双击走**右键菜单「ℹ 详情」**。改 `qt_big_view.DOUBLE_CLICK_MS` 一个数即可
- **Tk 侧只能用系统的 0.5s**：实测 `SystemParametersInfoW(SPI_SETDOUBLECLICKTIME)` 把
  `GetDoubleClickTime()` 改成 1500ms 后，真实鼠标事件下 0.5/0.9/1.2s 的两下**仍然不算双击**，
  系统那套判定不认这个改写；控制面板的滑块最长也只到 0.9s。手慢的用户在 Tk 列表里用
  **右键菜单「ℹ 查看详情」**（放大查看的表格和卡片视图都绑了），不依赖时间
- **右键菜单里有全部单行操作**：两个视图（表格/卡片）都有「ℹ 详情 / 📂 打开所在位置 /
  🗑 移出清单 / ☑ 选中·☐ 取消选中 / 🌐 联网搜索」，都不依赖双击（也是实测弹得出来）
- 排查用日志还在：`~/.minecraft_migrate_clicks.log`（只留最近 400 行），详情窗弹出时会写一行
  `detail row=... visible=... geom=...`
- `双击间隙测试.py` 留着，但改成**纯诊断**（量你的手速，和当前的窗口值比一比），
  它不改任何设置，程序也不读它量出来的值

- **界面按钮可显示/隐藏 + 调顺序**（设置 →「界面按钮」）：除了主界面那七排，还包含
  **主界面右上角**（⚙ 设置 / 🎨 主题）、**放大查看窗口**、**日志放大查看** 三组。
  主界面的按钮改完**立刻**带动画生效；窗口里的按钮是那个窗口**下次打开**时生效
  （它们是每次打开现建的）。放大查看的「多选」Tk 版是一个下拉、Qt 版是三个按钮，
  同一组 key 各取所需，所以标签上标了 (Tk)/(Qt)。对话框自带的 确定/取消/关闭 不参与隐藏
- **迁移/扫描期间禁用范围**：开始迁移、回滚、扫描、清单增删改、路径浏览/填充、设置/主题、
  日志工具条 —— 全部置灰（`_refresh_busy_state`），避免中途改配置

### 🎨 界面与交互
- **深色/浅色主题**：一键切换，颜色语义统一
- **圆角文本框**（`utils/helpers.RoundedTextArea`）：模组清单 / config 清单 / 执行日志 /
  日志放大查看 / 变更日志提取框，原来都是方角的 `ScrolledText`。做法是"垫一张圆角底图 +
  把 Text 往里缩"，和圆角输入框同一套（radius 8 / pad 9，底图 4 倍超采样抗锯齿，
  拖动时先用 1 倍、停手 160ms 后补精细版）。**pad 必须 ≥ radius**：Text 是方的、盖在
  底图上，只留 pad 这一圈，留窄了就只看得到圆角弧最外面一点、看着还是直角。
  **正在编辑的那个框描边变亮蓝并加粗到 2px**（和圆角输入框同一套反馈），失焦回低调灰
- **全窗口按钮统一为"灵动"款**（`utils/helpers.create_gradient_button`，参数对齐 Qt 版
  `AnimButton`）：圆角 8px + 渐变 + 投影；**悬停浮起 1.6px 并扫过一道光**（190ms OutBack
  带过冲 + 340ms 亮带）、**按下沉 1.4px、松手 200ms OutBack 弹回**、禁用时整颗变灰。
  动画用"按档位预生成的帧图 + 只改坐标/itemconfigure"实现，实测稳定态 ~0.01ms/帧；
  首次悬停那一颗要现生成帧图（~7ms），之后全走缓存
- **圆角是按"按钮面"自己的尺寸渲染的**（不是从整图裁）：圆角弧只有 8px，裁掉四周留白
  会把弧的外半段切掉、角看着就是直角，鼠标一碰（面浮起来）轮廓还会挪，显得"圆角不统一"。
  混亮也只混 RGB、保留 alpha，避免四角出现半透明白边
- **大列表性能优化**：有界扫描线程池 + 分批 UI 更新 + 搜索防抖，上千条目不卡顿
- **路径安全校验**：源/目标路径有效性检测，config 清单自动拦截 `..` 越界与绝对路径
- **文件拖拽**：直接把 `.jar` / 配置文件拖进窗口即可添加
- **单实例运行**：重复启动会把已有窗口叫回来（挂在托盘里也能叫），避免多开冲突
- **后台运行**：关窗口可选收进系统托盘继续跑，任务结束弹 Windows 通知
- **设置窗分标签页**：`🎨 外观与启动 / 🚚 迁移与分类 / 🗂 放大查看 / 🔘 界面按钮 /
  🚪 后台与退出`。标签是**自己画的圆角药丸**（`ui/rounded_tabs.py`，和渐变按钮共用同一套
  3 倍超采样出图，边缘抗锯齿）：切页时选中块按 OutCubic **滑过去**（170ms）、页面从下方
  10px **滑到位**（150ms）、悬停变浅色；窗口按最大那一页定尺寸，换页不跳、内容不被裁

## 📦 下载与安装

### 方法一：使用预编译可执行文件（推荐）
- 下载打包好的 `.exe`，双击运行即可，无需安装 Python 或任何依赖
- 若拖拽文件进窗口失效，说明打包时未附带 `tkinterdnd2`，请用方法二重新打包（见下文）

### 方法二：从源码运行

1. 克隆 / 下载本项目（进入 `Minecraft迁移工具/` 目录）
2. 安装依赖：

   ```bash
   pip install tendo winotify tkinterdnd2 pillow pywin32 pywinstyles
   ```

3. 运行：

   ```bash
   python app.py
   ```

> **提示**：`winotify` 用于 Windows 通知，`tkinterdnd2` 用于文件拖拽，
> `pillow` 用于主题切换时的圆形过渡（需要截取窗口画面），`pywin32` 用于系统托盘
> （关窗口后挂在后台）。若打包后拖拽失效，通常就是漏了 `tkinterdnd2`；
> 若关窗口直接退出、没有托盘图标，通常就是漏了 `pywin32`。

## 🎮 使用指南

### 基本流程

1. **选择源实例根目录**（📤 旧版）
   例如：`D:\.minecraft\versions\1.20.1-old`（该目录下应直接包含 `mods`、`saves`、`config`、`options.txt`）

2. **选择目标实例根目录**（📥 新版）
   例如：`D:\.minecraft\versions\1.21-new`

   > 也可以用「← 使用新版路径填充」一键把目标路径复制到源路径，方便快速测试。

3. **填写存档名称**（存档文件夹名，例如 `我的生存世界`）
   右侧会实时显示该存档在源目录下是否存在（✅ / ❌）。

4. **编辑模组清单**（每行一个 `.jar`）
   - 点「从变更日志导入」自动提取 `Added / Updated` 模组列表
   - 点「扫描模组差异」自动比对源/目标 `mods` 目录并生成清单
   - 点「添加模组」或直接拖拽 `.jar` 进清单
   - 需要时点「放大查看」用大窗口搜索、排序、检测存在性

5. **编辑 Config 清单**（每行一个相对路径，指向源 `config` 目录）
   - 可「从源 config 导入所有条目」「浏览添加文件夹/文件」，或直接拖拽

6. **选择选项**
   - ☑ **模拟运行**：只显示操作，不实际修改文件（建议首次先模拟）
   - ☑ **覆盖已存在的模组**：目标已有同名模组时是否覆盖

7. **点击 🚀 开始迁移**
   迁移前会先做磁盘空间检查，并备份目标实例。

### 关窗口 = 自己选：挂后台还是直接退出

- 点窗口右上角的 ❌（当前没有任务在跑）会弹一个小窗问一次：
  - **收进托盘继续运行** → 程序留在**系统托盘**（任务栏右下角）继续跑，点托盘图标可以再打开；
  - **直接退出** → 关掉程序；
  - **取消** → 返回程序。
  - 勾上「记住我的选择，以后不再询问」就按这次的选择固定下来，不再每次问。
- 之后想改：**右键任务栏里的托盘图标** → 勾选 / 取消「关闭窗口时收进托盘」。
- **迁移 / 扫描进行中时，窗口不能被直接关闭**：
  - 点 ❌ 只会问「要不要收进托盘继续跑」——选**是**就收到托盘后台跑完（结束弹通知），选**否**就返回程序；**没有"强制退出"这个选项**。
  - 没装 `pywin32`（没有托盘可挂）时点 ❌ 只弹一条提示，窗口不关，等任务结束再说。
  - 托盘菜单里的「退出」在任务进行中也会再确认一次，默认选**否**。
  - 迁移进度窗口右上角的 ❌ 同样要先确认（界面上那个「取消」按钮是明确意图，不拦）。
- 托盘图标：**左键单击**（或再启动一次程序）重新打开主界面；**右键**菜单：打开主界面 / 关闭窗口时收进托盘 / 退出。
- 窗口挂在托盘里时，扫描出的差异窗口不会突然弹出来打扰你，等主界面叫回来再显示。
- 托盘需要 `pywin32`；没装的话关闭按钮就恢复成"直接退出"（但任务进行中仍然拦着）。

### 使用 auto-py-to-exe 打包（推荐）

1. 安装：`pip install auto-py-to-exe`
2. 运行：`python -m auto_py_to_exe`（或双击项目根目录下的 `打包.bat`）
3. 配置要点：
   - **脚本**：`app.py`
   - **Onefile**：勾选（单文件）
   - **Windowed (no console)**：勾选（无控制台窗口）
   - **Icon**：`1.ico`
   - **tkinterdnd2**：仅加 `--hidden-import tkinterdnd2` 不够——它还需要收集包里的 `tkdnd` 动态库和 tcl 脚本，否则打包后拖拽会失效。

4. **让 PyInstaller 自动收集 tkinterdnd2 平台资源（重要）**
   因为 `tkinterdnd2` 除 Python 代码外，还带平台相关的 `tkdnd\win-x64\` 等目录（含 `libtkdnd2.10.1.dll` 和多个 `.tcl`），PyInstaller 默认不会收这些。项目已提供专用 hook：`hook_tkinterdnd2.py`。

   - **auto-py-to-exe**：在 **Advanced → `--additional-hooks-dir`** 填入本项目根目录（即 `hook_tkinterdnd2.py` 所在目录），并在 **`--collect-data`** 留空即可（hook 已代劳）。或者直接把项目根目录加到 **Additional Files / `--additional-hooks-dir`**。
   - **命令行 PyInstaller**：
     ```bash
     pyinstaller --onefile --windowed --icon 1.ico \
       --additional-hooks-dir . \
       --hidden-import tkinterdnd2 \
       app.py
     ```
   - 若两种方式都拿不到，可用 `--collect-data tkinterdnd2` 直接声明收集该包全部数据文件。

5. **打包后务必自测**：拖几个 `.jar` 文件进窗口，确认拖拽可用（能添加、能响应）。若无效，多半是 `tkdnd` 资源没被打进去。

- **双击间隙诊断**（`双击间隙测试.py`）：双击 10 次量出你的手速，和当前的窗口值比一比；

- 存档名称输入实时检测“是否存在”（去掉原手动“检查”按钮）
- 模组详情窗口新增 Modrinth 联网搜索（最相似匹配、最新版本、下载/项目链接）
- 主界面与全部子窗口按钮统一为渐变风格
- 放大查看：新添加模组黄色高亮、外部变更自动刷新、搜索防抖
- 大列表性能优化：有界扫描线程池 + 分批 UI 更新，上千条目不卡顿
- **放大查看新增 PySide6 试点窗口**（设置里可切换回 Tk 版）：无边框圆角 + 投影、
  卡片视图、选中蓝底/左侧高亮条的逐帧动画、Qt 原生平滑滚动与排序

**🐛 修复**
- **迁移按钮可能被触发第二次**：准备阶段（校验清单 / 统计文件 / 磁盘检查）那几秒里，只要出现过弹窗（messagebox 会开嵌套事件循环），排队的那次点击就会被派发，而那时 _migration_running 还没置位 —— 一次点击变两次迁移。现在从进入 start_migration 的第一行就置 _starting 标记并立刻把按钮变灰，准备阶段内第二次点击既不派发也不再进入流程；校验失败等提前返回会把按钮恢复
- **修复启动卡在动画、主界面一直不显形**：闪屏动画自己排下一帧用的延时会在"一帧耗时超过
  帧预算"时缩到 1ms，而 Tcl 的定时器精度只有毫秒级——刚排上的定时器在 `root.update()`
  眼里立刻又到期，`update()` 就永远返回不了（实测延时 1/2ms 必卡，≥10ms 时每次只处理 1 帧）。
  现在给下一帧的延时加了 10ms 下限
- **启动动画不再被主线程构建拖卡**：真正的原因不是"画得慢"（Tk 每帧 5ms、Qt 3.8ms），
  而是构建主界面那 1.2 秒里 `on_stage` 只被调用 30 次、**最大间隔 325ms**（这期间闪屏
  完全静止，整体只有 ~25fps）。现在把启动动画放进**独立进程**（PySide6 画，
  `ui/splash_qt.py`）：主线程连续忙 1.95 秒期间它照样 **59~62fps**；启动总耗时不变
  （子进程与 emoji 预热并行，实测主窗口 2.89/2.97s vs 进程内 2.76/3.13s）。
  拿不到 PySide6、或子进程 1.2 秒内没就绪，就自动回落到进程内的 Tk 闪屏
  （也可用环境变量 `DSH_NO_QT_SPLASH=1` 手动关掉）；父进程若异常退出，子进程收到
  stdin EOF 会立即退出，不留孤儿进程（实测已验）
- 闪屏渲染提速：卡片与立方体分成两个画布图元、立方体只传"不透明补丁"
  （同样 210×210：半透明上传 5.66ms → 0.29ms）、缩放没变就跳过 `SetWindowRgn`
- 修复渐变按钮改文字/禁用时的不兼容问题（新增 `set_text` / `state` / `set_command`）
- 修复差异窗口排序、全选、双击详情的交互问题
