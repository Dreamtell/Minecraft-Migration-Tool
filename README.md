# 🧳 Minecraft 存档迁移工具（迁移工坊）

一款用于在不同 Minecraft 整合包实例之间迁移 **模组、配置文件、存档和设置** 的图形化工具。

纯 Python + Tkinter 实现，**完全免费、开源、纯中文界面**，无需联网即可完成核心迁移（模组联网搜索为可选用途）。

---

## ✨ 功能特性

### 🚀 核心迁移
- **一键迁移**：从旧版（源）整合包复制到新版（目标）整合包，保留你的自定义配置与存档
- **三步迁移流程**：模组 → 存档（`saves/存档名`）→ `config` 内容。
  **其它文件一律不自动带** —— 包括以前被默认复制的 `options.txt`：想要什么就在
  「其它文件」页自己加（那儿有个 `＋ options.txt` 一键加进清单）
- **模拟运行**：勾选后只预览将执行的操作，不实际改动任何文件，放心调整
- **迁移前磁盘空间检查**：自动校验目标磁盘能否容纳「迁移数据 + 目标备份」，不足时给出拦截
- **备份与回滚**：迁移前自动备份目标实例里**这次迁移会动的每一样东西** ——
  `mods / config / saves` 三个目录，**加上「其它文件」清单里的每一条**
  （清单是动态的，所以备份时按这次的清单走：覆盖的条目留下旧内容，回滚能还原；
  迁移前不存在的条目记一笔，回滚时删掉）。清单里加了 `screenshots/` 这种大目录时，
  备份体积会跟着涨（磁盘空间检查用的是目标实例总大小，已经算进去了）
- **迁移历史记录**：记录每次迁移的时间、来源、目标、模组与 config 数量，支持回滚标记

### 🧩 模组差异识别
- **元数据级差异扫描**：读取 jar 内的 `fabric.mod.json` / `META-INF/mods.toml`，按 `Mod ID` 与版本号识别差异（支持 Fabric 与 Forge）
- **三类状态**：新增、更新、目标独有
- **按状态批量选择**：一键全选「新增」「更新」「目标独有」
- **智能排序**：按文件名、状态、类型、Mod ID、版本、大小排序
- **双击查看详情**：查看完整元数据（作者、描述、依赖等）
- **默认视图可选**：差异窗口打开时用「列表」还是「卡片」（卡片带图标 + 描述，看得清内容），
  在设置 →「🗂 放大查看」→「差异窗口打开时用哪个视图」里选；窗口开着时也能随时点按钮切

### 🔍 联网搜模组（可选）
- 基于 **Modrinth 公开 API**（免费、无需密钥）
- **最相似匹配**：本地模组自动匹配最相似的项目，自动置顶
- **按你的实例过滤**：自动识别实例的 MC 版本与加载器，只搜适配这一组的项目，
  「最新版本」也取这一组的构建（可手动改成别的版本或关掉过滤）
- **表格 / 卡片两种视图**：和放大查看、差异窗口同一套自绘卡片（按钮同一颗「🗂 卡片视图」）；
  卡片上有状态圆点、加载器与分类标签、版本与描述，鼠标划过有高亮、点一下选中，
  底部那几个按钮作用在选中的那一行
- 展示最新版本、下载量、下载/项目链接，支持复制与跳转
- **模组详情窗口**：图标 + 中文名 + 版本 / 类型 / 运行环境 / 分类徽章，作者 / 依赖 / Mod ID 分栏，
  描述独立成块（自动换行、可滚动）；底部「打开所在文件夹 / 复制 Mod ID / 复制文件名」
- 只读搜索，不修改任何本地文件；无网络时核心迁移功能不受影响

### 📁 清单管理与放大查看
- 模组清单 / config 清单可手动编辑、从源目录导入、拖拽添加
- **放大查看窗口**：可多选（勾选排序）、搜索、检测存在性、添加/删除、拖拽
- **卡片视图**（模组）：PCL2 风格圆角卡片，显示图标 / 名称 / 版本 / 状态 / 分类标签 / 描述
  - 鼠标滚轮与 `↑↓ PageUp PageDown Home End` 平滑滚动（像素级，不是整行跳）
  - **单击卡片 = 选中**（点击处整张卡变蓝，带渐变；没有单独的勾选框），`空格` 切换当前行选中；
    **同一行快速点两下 = 看详情**
    （双击间隙 0.18s，比系统默认小，快速连点不会误弹详情窗）
  - 右键菜单可看详情 / 在文件夹中定位 / 从清单移除
  - 右上角 `☑ 多选`：全选 / 反选 / 清空勾选 / 删除选中（表格视图同样可用）
  - **加载器品牌色**：Fabric 用它 logo 上那块布料的米黄 `#dbb69b`（配深棕字），Quilt 紫 `#8b5cf6`、
    NeoForge 橙 `#f16436`、Forge 钢灰蓝 `#5b6e7f`；卡片标签和详情窗口的"类型"徽章都用这套色
  - **打开中提示**：点「📂 放大查看」后按钮**立刻**变成 `⏳ 打开中…` 并变灰禁用，窗口出来再恢复
    （大清单建窗口要几百毫秒，这期间界面本来是不刷的；模组/config/日志三处都一样）
  - **选中样式**：没有勾选框。选中时浅蓝高亮**从左往右扫出来**，同时左端那条蓝色竖杠
    **从中间往上下延伸**（约 190ms，缓出曲线，竖杠先立住、底色再扫完）；再点则反向收回。
    表格视图没有这张卡，选中就是整行蓝底（同一套配色）
  - **选中汇总**：工具栏实时显示「已选 N / 总数 项」和「存在 X · 缺失 Y」，
    勾选、全选/反选/清空、删除、扫描回数据、切主题都会跟着更新（数字带滚动动画）
- **新添加高亮**：本次会话新加的模组用黄色高亮提示
- **列表总览条（VSCode minimap 那种）**：放大查看 / 模组差异窗口的列表**右侧**有一条竖缩略图
  —— 每一行一个小色块（差异窗按状态：新增绿 / 更新橙 / 降级红 / 目标独有灰；
  放大查看按勾选蓝 / 缺失红 / 新加橙 / 存在绿），色块是**压淡的半透明色**
  （约 0.65 浓度 —— 总览是"看分布"的，原色铺满一条太抢眼），半透明方框圈出当前看得见的那一段，
  **点一下或按住拖可跳转**（点到的那一行对到视口中间，和 VSCode 手感一致）；
  行数少、不够一屏时方框占满，只当"整份列表长什么样"的缩略图看
- **实时刷新**：放大查看窗口会随主界面清单的外部变更自动更新（Qt 版与 Tk 回退版都有）；
  编辑模式里手打的内容也会同步过去（防抖 300ms，停下来再推），
  子进程收到后重建列表但**保留勾选态与扫描结果**，只给新来的条目重新扫描
- **实时存档检测**：输入存档名即实时显示“存档是否存在”，无需手动点按钮
- **「其它文件」清单是唯一依据**：迁移除了三个清单（模组 / config / 存档）之外，
  只带这份清单里列出的东西 —— **空清单 = 其它一律不动**。常带的条目在清单页用
  `＋ options.txt` 和 `＋ 常用目录 ▾` 一键加进去（`shaderpacks/`、`resourcepacks/`、
  `schematics/`、`XaeroWorldMap/`、`XaeroWaypoints/`、`xaero/`、`journeymap/`、
  `kubejs/`、`defaultconfigs/`、`local/`、`screenshots/`、`servers.dat`、
  `optionsof.txt`、`iris.properties`）；源实例里没有的会拒绝加入并提示，
  加进来的会按你选的冲突策略（覆盖=先备份 / 跳过）走。
  > 以前这里有一组「默认携带的目录」勾选框：勾上的目录在迁移那一刻被自动并进临时清单，
  > 而且不写回清单（看不到也删不掉）。用户要求"之前默认带的东西现在都要自己选"，
  > 所以那套删了、统一到这里。老配置里勾过的条目会**自动并进清单一次**（日志会说明），
  > 之后清单就是唯一依据 —— 从清单里删掉就不会再带。

### 🏷️ 模组分类标签
- 默认按描述 / 名称里的**关键词推测**，界面上会明确标注“推测”
- 设置里可开启**联网获取真实分类**（Modrinth）：后台查询、结果缓存到
  `~/.minecraft_migrate_tags.json`，之后不再重复请求
- 只认**精确匹配**（slug / 标题一致）才采用，绝不拿搜索结果第一条凑数
- 断网 / 匹配不到会自动沿用推测结果；连续失败 3 次后本次运行不再尝试联网

### 🎨 界面与交互
- **深色/浅色主题**：一键切换，颜色语义统一
- **全窗口按钮统一为"灵动"款**（63 处按钮共用一个工厂，参数对齐 PySide6 试点窗口的
  `AnimButton`）：圆角 8px + 渐变 + 投影；悬停**浮起 1.6px 并扫过一道光**（190ms OutBack
  带过冲 + 340ms 亮带）、按下**沉 1.4px、松手 200ms OutBack 弹回**、禁用时整颗变灰
- **圆角文本框**：模组清单 / config 清单 / 执行日志 / 日志放大查看 统一为圆角外框，
  **正在编辑的那个框描边变亮蓝 2px**；底下仍是原生 `Text`，滚动/选择/快捷键都不受影响
- **圆角输入框**：所有单行输入框（路径 / 存档名 / 各种搜索框）统一为圆角、聚焦时主色描边；
  底下仍是原生 `Entry`，中文输入法、右键菜单、拖选、快捷键都不受影响
- **按钮显示/隐藏 + 自定义排序**：设置里可勾选、上下移动，显隐与换序带平滑滑动过渡
- **模组迁移标记**：可选给复制过去的模组加前缀符号（`★ ☆ ▶ ◆ ● ✦ ✚ 【新】 NEW_`），方便辨认
- **大列表性能优化**：有界扫描线程池 + 分批 UI 更新 + 搜索防抖，上千条目不卡顿
- **平滑滚动**：所有列表 / 文本区逐帧插值滚动，手感一致
- **文件任务互斥**：迁移进行中会给主窗口盖一层锁屏遮罩 —— 边框是**流动的红色渐变**
  （定长渐变瓦片绕圈平移，红光沿边框流），遮罩里**内嵌一份执行日志**（级别配色、平滑滚动与主日志一致，
  新日志实时追加），不用关窗口就能看进度；连静默后台模式也一样。锁屏期间**所有按钮一律禁用**
  （含右上角设置/主题、日志区那三个）；反过来说，只要**扫描差异 / 检查存在性 / 导入变更日志 /
  回滚 / 大窗口检测存在性**在跑，点「开始迁移」会被直接拒绝并说明是哪个任务在占用
  （**模拟运行同样拦**）
- **锁屏方式可选**：设置 →「🔒 任务与锁定」三选一 —— 正式+模拟都锁 / 只锁正式迁移（模拟不盖遮罩）/
  不锁屏；后两种按钮照样全部禁用，只是不盖遮罩
- **迁移完成态**：跑完不会“啪”地一下把遮罩收掉 —— 先在锁屏日志里打印**迁移总结**
  （结果 / 耗时 / 三份清单条数 / 出错条目最多 5 条），头部 🔒 变成 ✅（有失败则 ⚠️），
  边框同时从红**带过渡地渐变**成绿色（有失败变橙色，约 10 帧 0.45 秒）；
  默认停在完成态等你**按任意键（或点一下）**再收起，设置里也能改成 2 秒后自动收起
- **路径安全校验**：源/目标路径有效性检测，config 清单自动拦截 `..` 越界与绝对路径
- **文件拖拽**：直接把 `.jar` / 配置文件拖进窗口即可添加
- **单实例运行**：重复启动会把已有窗口叫回来（挂在托盘里也能叫），避免多开冲突
- **后台运行**：关窗口可选收进系统托盘继续跑，任务结束弹 Windows 通知

## 📦 下载与安装

### 方法一：使用预编译可执行文件（推荐）
- 下载打包好的 `.exe`，双击运行即可，无需安装 Python 或任何依赖
- 若拖拽文件进窗口失效，说明打包时未附带 `tkinterdnd2`，请用方法二重新打包（见下文）

### 方法二：从源码运行

1. 克隆 / 下载本项目（进入 `Minecraft迁移工具/` 目录）
2. 安装依赖：

   ```bash
   pip install tendo winotify tkinterdnd2 pillow pywin32 pywinstyles
   ```

3. 运行：

   ```bash
   python app.py
   ```

> **提示**：`winotify` 用于 Windows 通知，`tkinterdnd2` 用于文件拖拽，
> `pillow` 用于主题切换时的圆形过渡（需要截取窗口画面），`pywin32` 用于系统托盘
> （关窗口后挂在后台）。若打包后拖拽失效，通常就是漏了 `tkinterdnd2`；
> 若关窗口直接退出、没有托盘图标，通常就是漏了 `pywin32`。

## 🎮 使用指南

### 基本流程

1. **选择源实例根目录**（📤 旧版）
   例如：`D:\.minecraft\versions\1.20.1-old`（该目录下应直接包含 `mods`、`saves`、`config`、`options.txt`）

2. **选择目标实例根目录**（📥 新版）
   例如：`D:\.minecraft\versions\1.21-new`

   > 也可以用「← 使用新版路径填充」一键把目标路径复制到源路径，方便快速测试。

3. **填写存档名称**（存档文件夹名，例如 `我的生存世界`）
   右侧会实时显示该存档在源目录下是否存在（✅ / ❌）。

4. **编辑模组清单**（每行一个 `.jar`）
   - 点「从变更日志导入」自动提取 `Added / Updated` 模组列表
   - 点「扫描模组差异」自动比对源/目标 `mods` 目录并生成清单
   - 点「添加模组」或直接拖拽 `.jar` 进清单
   - 需要时点「放大查看」用大窗口搜索、排序、检测存在性

5. **编辑 Config 清单**（每行一个相对路径，指向源 `config` 目录）
   - 可「从源 config 导入所有条目」「浏览添加文件夹/文件」，或直接拖拽

6. **选择选项**
   - ☑ **模拟运行**：只显示操作，不实际修改文件（建议首次先模拟）
   - ☑ **覆盖已存在的模组**：目标已有同名模组时是否覆盖

7. **点击 🚀 开始迁移**
   迁移前会先做磁盘空间检查，并备份目标实例。

### 关窗口 = 自己选：挂后台还是直接退出

- 点窗口右上角的 ❌（当前没有任务在跑）会弹一个小窗问一次：
  - **收进托盘继续运行** → 程序留在**系统托盘**（任务栏右下角）继续跑，点托盘图标可以再打开；
  - **直接退出** → 关掉程序；
  - **取消** → 返回程序。
  - 勾上「记住我的选择，以后不再询问」就按这次的选择固定下来，不再每次问。
- 之后想改：**右键任务栏里的托盘图标** → 勾选 / 取消「关闭窗口时收进托盘」。
- **迁移 / 扫描进行中时，窗口不能被直接关闭**：
  - 点 ❌ 只会问「要不要收进托盘继续跑」——选**是**就收到托盘后台跑完（结束弹通知），选**否**就返回程序；**没有"强制退出"这个选项**。
  - 没装 `pywin32`（没有托盘可挂）时点 ❌ 只弹一条提示，窗口不关，等任务结束再说。
  - 托盘菜单里的「退出」在任务进行中也会再确认一次，默认选**否**。
  - 迁移进度窗口右上角的 ❌ 同样要先确认（界面上那个「取消」按钮是明确意图，不拦）。
- 托盘图标：**左键单击**（或再启动一次程序）重新打开主界面；**右键**菜单：打开主界面 / 关闭窗口时收进托盘 / 退出。
- 窗口挂在托盘里时，扫描出的差异窗口不会突然弹出来打扰你，等主界面叫回来再显示。
- 托盘需要 `pywin32`；没装的话关闭按钮就恢复成"直接退出"（但任务进行中仍然拦着）。

### 使用 auto-py-to-exe 打包（推荐）

1. 安装：`pip install auto-py-to-exe`
2. 运行：`python -m auto_py_to_exe`（或双击项目根目录下的 `打包.bat`）
3. 配置要点：
   - **脚本**：`app.py`
   - **Onefile**：勾选（单文件）
   - **Windowed (no console)**：勾选（无控制台窗口）
   - **Icon**：`1.ico`
   - **tkinterdnd2**：仅加 `--hidden-import tkinterdnd2` 不够——它还需要收集包里的 `tkdnd` 动态库和 tcl 脚本，否则打包后拖拽会失效。

4. **让 PyInstaller 自动收集 tkinterdnd2 平台资源（重要）**
   因为 `tkinterdnd2` 除 Python 代码外，还带平台相关的 `tkdnd\win-x64\` 等目录（含 `libtkdnd2.10.1.dll` 和多个 `.tcl`），PyInstaller 默认不会收这些。项目已提供专用 hook：`hook_tkinterdnd2.py`。

   - **auto-py-to-exe**：在 **Advanced → `--additional-hooks-dir`** 填入本项目根目录（即 `hook_tkinterdnd2.py` 所在目录），并在 **`--collect-data`** 留空即可（hook 已代劳）。或者直接把项目根目录加到 **Additional Files / `--additional-hooks-dir`**。
   - **命令行 PyInstaller**：
     ```bash
     pyinstaller --onefile --windowed --icon 1.ico \
       --additional-hooks-dir . \
       --hidden-import tkinterdnd2 \
       app.py
     ```
   - 若两种方式都拿不到，可用 `--collect-data tkinterdnd2` 直接声明收集该包全部数据文件。

5. **打包后务必自测**：拖几个 `.jar` 文件进窗口，确认拖拽可用（能添加、能响应）。若无效，多半是 `tkdnd` 资源没被打进去。

  重建图片条目 —— 拿旧 id 调 `itemconfig` 是静默无效的，表现为"文字都在、卡片底图全不见"
- **线程调优：扫描并发降到 3；跨线程一律走队列**（实测数据见 `_dctest/基准_扫描线程.py`，
  450 个真 jar / 108MB）：

  | 线程数 | 1 | 2 | 3 | 4 | 6 | 8 | 12 |
  |---|---|---|---|---|---|---|---|
  | 扫描耗时 | 0.40s | 0.42 | 0.42 | 0.41 | 0.43 | 0.43 | 0.43 |
  | 界面最坏延迟 | 13ms | 13 | 13 | 14 | 15 | **17** | **17** |

  解析是"解 zip + 解 JSON"的 Python 活，**卡在 GIL 上**：加线程换不来速度，只会让界面
  线程在 GIL 上排队。所以扫描池从 4 降到 **3**（和 Qt 侧早就调好的并发数一致）；"源 /
  目标合成一个池"也量过，没有收益，不做。
  另外把**所有跨线程碰 Tk 的地方**统一成"队列 + 主线程泵"：tkinter 明确声明 Tk 不是
  线程安全的，实测事件循环不是 mainloop 时（验证脚本用 `update()` 泵的那种）从 worker
  调 `root.after` 会抛 `main thread is not in main loop`，那条日志 / 那次收尾就悄悄丢了。
  现在：扫描结果走进度队列（原来是在扫描线程里 `root.after` 送回结果，结果会和"进度
  结束哨兵"抢同一个队列，得让 `None` 之后继续轮询）、后台日志走 `_ui_post`、迁移收尾
  （解锁 + 边框红转绿）也走 `_ui_post`、联网搜索的过滤条件改成**主线程读好再传进线程**。
- **重复打开窗口直接置顶 + 主程序单例**：Windows 有"前台锁"——不是当前前台进程的窗口，
  系统会**忽略** `SetForegroundWindow`，所以 Tk 的 `lift()+focus_force()`、Qt 的
  `raise_()+activateWindow()` 往往只是"任务栏闪一下、窗口还压在后面"。现在统一走
  `helpers.force_foreground()`：`SW_RESTORE` → `SetForegroundWindow` → 临时
  `HWND_TOPMOST` 再摘掉（这一步绕开前台锁）。用在：**放大查看 / 模组差异 / 设置 /
  迁移历史 / 变更日志导入 / 模组详情 / 日志放大查看**的"重复打开=聚焦已有窗口"，
  以及第二个实例把主界面叫回来时（先 `AllowSetForegroundWindow(ASFW_ANY)` 授权）。
  **最小化 / 缩在托盘**都算：`IsIconic` 就先 `SW_RESTORE`，所以"窗口最小化着再双击一次
  图标"也能把主界面还原并叫到最前。
  两个坑：Tk 的 `wm frame` 还在 Tk 自己一层包装里，必须再取 `GetAncestor(GA_ROOT)`，
  否则 `SetForegroundWindow` "成功"但前台窗口不变（实测）；而 `wm frame` 返回的是
  **十六进制字符串**（`0x2020922`），`int()` 不带 base 会抛异常、静默退到子窗口 HWND，
  于是"最小化还原"就失效了（都是实测踩出来的）；配置文件路径也支持
  `MCTOOL_CONFIG` 环境变量了，验证脚本跑真程序时不会碰用户的真实配置
- **分段选择控件**（自绘）：互斥选项排成一条药丸，选中的那段用**滑动的色块**浮起来
  （130ms OutCubic、4 倍超采样抗锯齿、未选中段悬停给一层淡底、跟随主题重出图）。
  先用它替掉「其它文件」页那对 `tk.Radiobutton`（「覆盖（先备份）/ 跳过（目标保持不变）」）
  —— 系统小圆点 + 老式字重跟这套自绘 UI 明显不是一路
- **放大查看 / 模组差异开着时，主界面编辑不可用**：这两个窗口手里是**打开那一刻的清单
  快照**（而且会往回写、做增删同步），主界面同时还在编辑，就是两边抢同一份清单 ——
  之前那个"主界面编辑的内容被写回盖掉"的 bug 正是从这儿来的。现在窗口一开：三个清单
  文本框强制只读、编辑开关**灰掉点不动**（说明写清是哪个窗口拦着，鼠标也不变手型）；

**🐛 修复**
- 修复**模组详情里的描述框滚轮是"整行跳"**（Qt 版）：全项目滚动点盘了一遍，就它是裸
  `QTextEdit`，其余早就是平滑的（Tk 侧 12 处全挂 `SmoothScroller`，Qt 侧表格/卡片都是
  `SmoothTable`/`SmoothCards`）。现在换成一个 `SmoothTextEdit`（同样的 `_SmoothWheel` 混入，
  一格约三行文字）。顺带留了个**全覆盖测试**：把每个窗口建出来递归遍历，凡是 Text /
  Treeview / Listbox / 自绘表格 / Qt 滚动区，都必须在平滑滚动登记表里（QComboBox 的原生
  弹出列表和表头除外，那两样不响应滚轮），再加一层源码级检查防止以后新窗口忘了配
- 修复**关掉放大查看 / 模组差异窗口之后，主界面编辑还是灰的、点不动**：这两个窗口跑在
  独立子进程里，而 `ensure_app()` 里 `setQuitOnLastWindowClosed(False)` 是"Qt 跑在 Tk
  主进程里"时代留的（关个 Qt 窗口不能把主进程带走）—— 在子进程里就变成**关窗后进程一直
  挂在后台**。主进程判断"窗口还开着没有"靠的正是"进程还在不在"，于是编辑锁不松。
  顺带还有一个一直没被发现的隐性 bug：关窗后再点「放大查看」只会给一个**已经没有窗口的
  进程**发 `raise`，窗口再也出不来（实测：关窗后 `poll()` 一直是 None、pid 不变）。
  现在子进程里把 `quitOnLastWindowClosed` 打开，并在窗口对象销毁时明确 `app.quit()`；
  主进程也接住子进程补发的 `close` 回执立刻解锁（两条路幂等）。
  顺带加了道保险：子进程每 1.5 秒看一眼**父进程还在不在**，不在就自己退 ——
  主界面崩掉 / 被强杀时不会再在桌面上留一个没人管的孤儿窗口
  （判活要看 `GetExitCodeProcess == STILL_ACTIVE`：`OpenProcess` 对已退出的进程
  照样给句柄，光看它就永远"父还在"）。
  实测：关窗 → 进程退出码 0、锁解开、再点放大查看是**新进程 + 新窗口**
- 修复**设置窗口尺寸不正常**：它原来是"按**最高那一页**撑开"的 —— 「🚚 迁移与分类」
  那页内容 816 高（四个分区框摞起来，跟文字折行关系不大：换行宽度从 580 调到 900
  也只降到 768），于是窗口变成 **700x926** 的一条窄柱，而且 `resizable(False, False)`
  用户还改不了。现在：宽度按最宽那页的**内容**给，高度给正常值 640 并钳进屏幕
  （`center_window` 只居中不裁剪，太高会顶出屏幕下沿），**每页自己滚** ——
  装不下才出滚动条（矮页自动收起那条灰杠）、切页各自记住位置；窗口也能缩放了（最小 660x460）
- 设置界面**滚轮改成平滑滚动**（和列表/文本框同一套 `SmoothScroller.for_canvas`）：
  `yscrollincrement=1` 做到像素级插值，滚一格是"起步→加速→落位"而不是一步跳 48px
  （实测：0 → 20ms 时 15px → 48px 落位）。滚轮统一由窗口按"当前那一页"转发，
  所以 `ttk.Treeview`、Text 这类自己有滚动的控件不会被抢（各滚各的）
- 修复**总览条里"选中的蓝"看着像半透明**（放大查看 / 模组差异共用这条）：条目一多，
  每个色块只有 1~3px 高，而原来画的是**圆角矩形**（半径 1px）—— 形状退化成一条细透镜，
  抗锯齿一平均颜色就被冲淡。实测 300 条时勾选蓝只剩 **64%** 的饱和度（`#2f7fd1`
  被冲成 `#5a9ad8` 那种），而"存在"的绿本来是**刻意**淡到 43% 当背景的，
  两者就分不出来了。现在：
  · 块高够（≥4px）→ 照旧圆角小方块；
  · 块高不够 → **一个像素行一个色、每个像素行只画一次**，既不叠色也不露白缝。
    顺带修掉另一个反向问题：原先细带子互相重叠，**半透明颜色叠一层深一层**，
    实测 1200 条时该淡下去的绿会叠到 76%、整条反而比稀疏时更艳
  · 实测（单色条，浅色/深色×7 种条数）：勾选蓝 **全程 1.00**（原色），
    存在绿 **全程 0.43**（正好是设计的浓度）
- 修复**实时同步的卡顿**（放大查看）：主界面清单变化时子进程要刷新列表，实测 1000 条
  · 内容跟它手里那份**一模一样**（包括它自己刚写回触发的那一趟）→ 直接返回，
    **26.5ms → 0.2ms**，一帧都不重画
  · 改动集中在**一整段**（末尾加一行 / 中间删一行 / 改一行 / 粘一段）且没有搜索词和排序
    → 走 `beginInsertRows` / `beginRemoveRows`；行数没变（改内容、换顺序）只发
    `dataChanged`，**连布局和滚动条都不动**。store 那层 **~25ms → 0.5ms**
  · 被换掉那一段里文本还留着的条目**复用原对象**，勾选态 / 扫描结果 / 图标不丢，
    也不会把刚扫好的上千条重扫一遍
  · 剩下的重画开销（实测表格视口 24ms、总览条 3.6ms、摘要行 3.3ms）是 Qt 画这张表
    本身的成本，跟数据变没变无关（空跑一次 `viewport().update()` 也是 24ms）
- 修复**放大查看看不到主界面刚改的清单**（Qt 版）：它跑在子进程里，只有 `raise` / `theme`
  两条命令，手里永远是"打开那一刻的快照"。现在主界面清单一变就推一条 `entries` 命令过去
  （`<<ModlistChanged>>` / `<<ConfigChanged>>` 那几条流程，外加手打的 `<<Modified>>`，
  防抖 300ms、同一份内容只推一次），子进程 `set_entries` 重建时**复用原有条目对象** ——
  勾选态、扫描出来的元数据、滚动位置都留着，只有新条目才重新扫描。Tk 回退版本来就有
  这套（`<<ModlistChanged>>`），这次是给 Qt 版补齐
- 修复**放大查看会把主界面编辑的内容还原**：放大查看手里是"打开那一刻的清单快照"，
  而写回一直是**整份覆盖** —— 在主界面编辑模式里改过之后（不管是窗口开着时改的，
  还是关掉窗口又重开的），它一关窗 / 一增删就把那份旧快照盖回去。现在写回只发
  **增删增量**（`utils.helpers.text_delta`），由主界面把变化应用到**当前**文本上：
  用户敲的行不动、滚动位置不跳；一样都没变时连一个字符都不碰。
  Qt 子进程和 Tk 回退版走同一套（`_apply_entries_delta`）
- 修复**鼠标移出列表后悬停高亮不消失**（放大查看 / 模组差异的表格与卡片）：清悬停原来是
  替换视图的 `leaveEvent`，但 Qt 根本不会把 `Leave` 转给它 ——
  `QAbstractScrollArea::viewportEvent()` 对 Leave 直接 `return false`
  （源码注释：let the viewport widget handle the event），`QAbstractItemView` 只清它
  自己内部的 hover 索引。改成盯 viewport 的事件过滤器（联网搜索那张表本来就是这么做的）
- 修复**按错误版本过滤后一条都搜不到的死胡同**：现在会自动放宽版本再搜一次，
  并在状态栏说明"可能是版本认错了"（Tk 回退版同样处理）
- 修复**联网搜索的「⬆ 可更新」几乎没参考价值**：线上版本号带 MC 前缀和加载器后缀
  （`mc1.20.1-0.5.13-fabric`），和本地裸版本号（`0.5.13`）比字符串**永远不相等**，
  等于每行都标"可更新"、这个标记就废了；现在先归一化再按版本号比大小，
  降级（本地比线上新）也不再冒充"可更新"
- 修复**没搜到版本时永远停在「获取中…」**：现在区分"该项目没有这套版本/加载器的构建"
  （会把条件写出来，如「无 1.20.1 · Fabric 的版本」）和"获取失败"，鼠标悬停还有解释
- 修复**联网搜索结果列表"看不出能选"**：Qt 版这张表原来是 `NoSelection` 且没有任何悬停反馈，
  鼠标划过去一片死寂、点一下也毫无变化，用户以为这列表选不了（也就不知道右边那几个按钮
  拿哪一行开刀）。现在鼠标划过整行变色 + 变手型光标，点一下整行保持高亮选中，
  按钮作用的就是选中的那一行；Tk 回退版详情窗口里的同一块搜索区也补上了悬停高亮
- 修复**自动猜的搜索词会漏尾巴**：`iris-mc1.20.1-1.6.5.jar` 原来猜成 `iris-mc`、
  `AppleSkin-mc1.20.1-forge-2.5.1.jar` 猜成 `AppleSkin-mc`，现在能剥干净（顺带去掉结尾的加载器）
- 修复**切主题时 Qt 窗口（放大查看 / 模组差异）不变色**：它们搬进独立子进程之后，
  主界面 `apply_theme` 里那句"遍历本进程的 Qt 窗口调 set_theme"就永远找不到对象了；
  现在改成给子进程发 `theme` 命令（子进程每 300ms 轮询执行，并回报成功/失败，
  失败会在主界面日志里记一条 ERROR）
- 修复渐变按钮改文字/禁用时的不兼容问题（新增 `set_text` / `state` / `set_command`）
- 修复差异窗口排序、全选、双击详情的交互问题
- 修复卡片视图勾选框点了没反应（`on_check` 从未被调用）
- 修复向上滚动异常快（滚动引擎的消费量必须是带符号位移，返回绝对值会让剩余量越滚越大）
- 修复超长描述模组导致的 1 秒级卡顿（文本截断由逐字符回退改为二分 + 缓存）
- 修复卡片视图鼠标位置与行号对不上（像素滚动后命中测试要算上零头）
- 修复**选中滑动动画卡顿**：高亮底色原来每帧都让 Pillow 重渲一张 880×58 圆角图（4 倍超采样 +
  缩放，实测 **9.8ms/帧**），改成"两块矩形 + 四个固定角圆"拼圆角（角图只渲一次，之后每帧只挪
  位置，**0.03ms**）—— 单帧 10ms 降到 **2.3ms**，动画才是真 60fps
- 修复**模组差异窗口**：① 选中高亮从来不显示 —— Treeview 里同一行挂多个都设了背景色的 tag 时，
  **靠前的那个生效**，而选中 tag 被排在了状态 tag 后面；② 表头点了不能排序（现在点表头即可排序、
